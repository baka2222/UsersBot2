# Система симуляции активности в Telegram-группах

Платформа имитирует живую активность аудитории: заранее подключённые
Telegram-аккаунты автоматически пишут сообщения по подготовленным сценариям,
когда в группе появляется сообщение-триггер.

Всё управление — через удобную веб-панель (Django + Jazzmin), программировать
ничего не нужно.

---

## Из чего состоит система

| Часть | Что делает |
|-------|-----------|
| **Веб-панель** (`python manage.py runserver`) | Настройка групп, аккаунтов, сценариев, шаблонов; просмотр журнала; **кнопка запуска бота**. |
| **Фоновый модуль** (бот) | Слушает группы и отправляет реплики по сценариям. Запускается/останавливается кнопкой из панели (раздел «Запуск бота»); отдельный терминал не нужен. |

Всё использует одну базу данных и **единый файл настроек `.env`** в корне проекта.

Есть два способа запуска:
- **Боевой (Docker)** — PostgreSQL + Nginx + веб-панель + отдельный контейнер бота. Рекомендуется. См. ниже.
- **Локальный (для разработки)** — SQLite и `runserver`. См. раздел «Установка (локально)».

## 🚀 Боевой запуск (Docker)

Нужен установленный **Docker** (с Docker Compose). Всё поднимается одной командой.

Архитектура — 4 контейнера:

| Контейнер | Роль |
|-----------|------|
| **db** | PostgreSQL (данные в томе, не теряются) |
| **web** | Веб-панель (Django + Gunicorn) |
| **nginx** | Принимает запросы, отдаёт статику, проксирует на панель |
| **bot** | Фоновый процесс симуляции (отдельно, перезапускается сам) |

### Шаги

```bash
# 1. Настройки: скопируйте пример и заполните
cp .env.example .env
```

В `.env` обязательно укажите:
- `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` (с https://my.telegram.org);
- `DJANGO_SECRET_KEY` — длинную случайную строку
  (`python -c "import secrets; print(secrets.token_urlsafe(50))"`);
- `POSTGRES_PASSWORD` — надёжный пароль базы;
- `DJANGO_SUPERUSER_USERNAME` / `DJANGO_SUPERUSER_PASSWORD` — логин и пароль для входа в панель;
- `DJANGO_ALLOWED_HOSTS` и `DJANGO_CSRF_TRUSTED_ORIGINS` — ваш домен/адрес
  (например `panel.example.com` и `https://panel.example.com`).

```bash
# 2. Сборка и запуск
docker compose up -d --build
```

Готово. Панель доступна на **http://ВАШ_АДРЕС:8080** (порт меняется в `.env` → `WEB_PORT`).
База, миграции, статика и администратор создаются автоматически при первом запуске.

### Полезные команды

```bash
docker compose ps                 # статус контейнеров
docker compose logs -f bot        # что делает бот
docker compose logs -f web        # логи панели
docker compose down               # остановить (данные сохраняются)
docker compose up -d --build      # обновить после изменений в коде
docker compose down -v            # ПОЛНЫЙ сброс, включая базу (осторожно!)
```

> **Про кнопку «Запуск бота».** В Docker контейнер `bot` работает постоянно, а кнопка
> в панели лишь включает/выключает отправку (флаг в базе). После `docker compose up`
> зайдите в раздел «Запуск бота» и нажмите **«▶ Запустить бота»**.

### Боевые рекомендации

- Поставьте перед Nginx HTTPS (например, Caddy/Traefik или certbot) — в `.env`
  тогда укажите `https://ваш-домен` в `DJANGO_CSRF_TRUSTED_ORIGINS`.
- Регулярно делайте бэкап тома базы (`pg_data`) и файла `.env`.
- Смените стандартный пароль администратора после первого входа.

### Если на этой же машине работает ещё один проект (например, AmirCashBot)

Проект использует собственное явное имя (`name: usersbot-simulator` в
`docker-compose.yml`), поэтому его контейнеры, тома и сеть **никогда не пересекутся**
с другими проектами, даже если у них похожая структура — это не зависит от названия
папки. Порты на хосте тоже разведены заранее:

| | UsersBot (этот проект) | AmirCashBot |
|---|---|---|
| Панель / Nginx | `8080` | `80` |
| PostgreSQL (с хоста) | `127.0.0.1:5434` | `127.0.0.1:5433` |

Если добавите третий похожий проект — просто выберите для него ещё не занятые
`WEB_PORT` и `POSTGRES_HOST_PORT` в его `.env`.

## Основные понятия

- **Группа** — чат в Telegram, где идёт общение.
- **Ведущий** — участник, чьи сообщения запускают сценарии (по умолчанию — только он).
- **Telegram-аккаунт** — подключённый аккаунт, от имени которого отправляются реплики. Один аккаунт можно использовать в нескольких группах.
- **Главный аккаунт (приложение)** — данные приложения Telegram (`api_id`/`api_hash` с [my.telegram.org](https://my.telegram.org)). Их можно завести **несколько** и распределить по ним подключённые аккаунты — чтобы снизить нагрузку на одно приложение и риск массовых блокировок. Аккаунт без выбранного приложения использует приложение «по умолчанию», а если такого нет — значения из `.env`.
- **Сценарий** — правило: на какое сообщение реагировать и какими репликами.
- **Реплика** — одно сообщение внутри сценария: какой аккаунт, через сколько секунд и что пишет.
- **Шаблон сообщения** — переиспользуемый текст для библиотеки.
- **Журнал работы** — история: кто написал триггер, какой аккаунт ответил, каким сценарием и когда.
- **Сообщения (инбокс)** — живые переписки подключённых аккаунтов: личные сообщения и чаты настроенных групп. Их видно в панели, и на них можно **отвечать вручную** от имени нужного аккаунта.

## Установка (локально, для разработки)

> Для боевого сервера используйте Docker (раздел выше). Этот способ — для разработки
> на своём компьютере: SQLite вместо PostgreSQL, без Nginx.

Требуется **Python 3.11+** (проверено на 3.13).

```powershell
# 1. Виртуальное окружение
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # Windows PowerShell
# source .venv/bin/activate           # Linux / macOS

# 2. Зависимости
pip install -r requirements.txt

# 3. Настройки — скопируйте пример и заполните
copy .env.example .env                # Windows
# cp .env.example .env                 # Linux / macOS
```

### Заполнение `.env`

Откройте файл `.env` и укажите как минимум данные Telegram-приложения:

1. Зайдите на <https://my.telegram.org> → **API development tools**.
2. Создайте приложение и скопируйте `api_id` и `api_hash`.
3. Впишите их в `.env`:

```
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=ваш_хэш
```

Остальные параметры (`.env`) уже имеют разумные значения по умолчанию.

### Подготовка базы данных

```powershell
python manage.py migrate
python manage.py createsuperuser        # придумайте логин и пароль для входа в панель
```

> Демонстрационный сценарий (пример «маркетинг» из ТЗ) можно создать командой
> `python manage.py seed_demo`.

## Запуск (локально)

Нужны **два** терминала (в обоих активировано виртуальное окружение):

```powershell
# Терминал 1 — веб-панель
python manage.py runserver
```
Панель: <http://127.0.0.1:8000/admin/>.

```powershell
# Терминал 2 — фоновый процесс бота
python manage.py run_bot
```
Он запускается и ждёт. Включение/выключение отправки — кнопкой в панели
(раздел **«Запуск бота»** → «▶ Запустить бота»).

> В Docker второй терминал не нужен — контейнер `bot` работает сам.

## Как настроить и провести занятие

> 📄 **Для не-программиста есть готовая PDF-инструкция по шагам:**
> [`Инструкция-по-панели.pdf`](Инструкция-по-панели.pdf) в корне проекта.
> Пересобрать её (если правили текст): `pip install fpdf2 && python docs/build_manual.py`.

Почти всё делается **в одном месте — в карточке группы**. Отдельно нужно только
один раз подключить аккаунты.

1. **(Необязательно) Заведите несколько «главных аккаунтов».** Панель →
   *Главные аккаунты (API Telegram)* → *Добавить*: название, `api_id`, `api_hash`
   (с [my.telegram.org](https://my.telegram.org)). Отметьте одно приложение «по
   умолчанию». Если ничего не заводить — используется приложение из `.env`.
   Смысл: распределить аккаунты по разным приложениям, чтобы снизить риск блокировок.

1. **Подключите аккаунты.** Панель → *Telegram-аккаунты* → *Добавить*.
   Укажите название, при желании выберите **приложение** (главный аккаунт), через
   которое он будет работать — **до** подключения, — сохраните и нажмите **«Подключить»**:
   - Шаг 1 — введите номер телефона, придёт код.
   - Шаг 2 — введите код (и облачный пароль, если включена двухэтапная проверка).

   **Код не приходит?** На шаге 1 есть кнопка **«Войти по QR-коду»**. Telegram
   иногда «молча» не доставляет код входа (при подозрении на api_id/IP) —
   QR-вход этого лишён: откройте Telegram на телефоне подключаемого аккаунта →
   *Настройки → Устройства → Подключить устройство* и отсканируйте показанный код.

2. **Создайте группу и настройте всё внутри неё.** Панель → *Группы* → *Добавить*.
   Вся настройка — на одной странице, сверху вниз:
   - **1. Название** — понятное имя группы.
   - **2. Какой чат в Telegram** — укажите ОДИН вариант: `@username`, ссылку-приглашение
     `https://t.me/+...` или числовой ID. Остальное определится само.
   - **3. Чьи сообщения запускают сценарии** — обычно @username ведущего.
   - **Аккаунты-участники** — отметьте, какие подключённые аккаунты будут отвечать
     (они должны быть **участниками** этого чата в Telegram).
   - **Сценарии** — прямо здесь же кнопкой «Добавить ещё один Сценарий»: задайте
     условие срабатывания, а внутри каждого сценария — **ответы аккаунтов**
     (кто, через сколько секунд и что пишет). Всё вложено в одну форму.

   Не забудьте нажать **«Сохранить»**.

3. **Запустите бота.** Панель → **«Запуск бота»** (кнопка в меню слева или сверху) →
   **«▶ Запустить бота»**. Проводите занятие. Когда ведущий отправит сообщение-триггер,
   выбранные аккаунты ответят через заданное время. После занятия — **«■ Остановить бота»**.

4. **Смотрите журнал.** Панель → *Журнал работы* — что и когда было отправлено.

5. **Переписывайтесь вручную.** Панель → **«Сообщения»** (кнопка в меню слева или сверху).
   Здесь собираются живые диалоги подключённых аккаунтов — **личные сообщения** и чаты
   **настроенных групп**. Откройте диалог кнопкой «Открыть» и напишите ответ прямо со
   страницы: в личке отвечает аккаунт этого диалога, в группе можно выбрать, **от имени
   какого аккаунта-участника** ответить. Так тренажёр работает максимально реалистично:
   будущие менеджеры и предприниматели ведут настоящую переписку.

   > Сообщения появляются и ответы отправляются, **пока запущен бот**. Если бот выключен,
   > ваш ответ сохранится и уйдёт автоматически, как только вы его запустите.

### Случайные числа в ответах

Чтобы сообщения выглядели живее, прямо в тексте ответа можно указывать **диапазоны
в фигурных скобках — `{от-до}`**. Вместо каждого подставится своё случайное число:

```
Босс, мы получили {50000-200000}$ за {5-30} дней, рост {2-8}%
```

Таких диапазонов может быть сколько угодно, у каждого своё число. Поддерживаются
дроби (`{1.5-3.5}`) и разделитель `..` (`{10..20}`). В блоке «Случайные числа»
у ответа есть галочка «разделять тысячи пробелами» (для вида `1 250 000`).

Есть и простой вариант: вставить в текст `{number}` — оно возьмёт диапазон из
полей «от» и «до» того же блока.

### Пример из ТЗ

Ведущий пишет: **«Сегодня поговорим о маркетинге.»**
Сценарий с триггером «маркетинг» (тип «содержит текст») отправляет:
- через 15 сек, Аккаунт №1: «А как определить целевую аудиторию?»
- через 30 сек, Аккаунт №2: «Какой рекламный канал лучше выбрать?»
- через 45 сек, Аккаунт №3: «Сколько нужно денег на первый запуск рекламы?»

Этот сценарий уже создан командой `seed_demo` — достаточно подключить аккаунты
и указать чат группы.

## Важные замечания

- **Группы, сценарии, реплики и шаблоны применяются на ходу** — бот сам
  перечитывает их (группы — в течение ~30 секунд), перезапуск не нужен.
- **Только после добавления нового аккаунта перезапустите бота** — аккаунты
  подключаются при старте. В Docker: `docker compose restart bot`. Локально —
  перезапустите `run_bot`.
- **Аккаунт должен быть участником группы**, иначе он не увидит сообщения и не
  сможет отвечать. Для приватных групп укажите ссылку-приглашение — при
  включённом `WORKER_AUTOJOIN=True` модуль попробует вступить сам.
- **Безопасность.** Файл `.env` и база данных содержат секреты (ключи и строки
  сессий, дающие полный доступ к аккаунтам). Не публикуйте их и храните в
  надёжном месте. `.env` добавлен в `.gitignore`.
- **Соблюдайте правила Telegram** и используйте только собственные аккаунты и
  группы, участники которых согласны на такой формат занятия.

## Защита аккаунтов от блокировок

Чтобы занятие не оборвалось из-за ограничений Telegram, в проект уже встроено
несколько мер (менять ничего не нужно — работает по умолчанию):

- **Правдоподобный «отпечаток» устройства.** Каждый аккаунт представляется Telegram
  как обычный настольный клиент на конкретном устройстве (свой стабильный вариант),
  а не как одинаковые боты. Работает при подключении и при работе бота.
  > Максимальный эффект — для аккаунтов, подключённых **после** этого обновления.
  > Ранее подключённые аккаунты для смены отпечатка достаточно переподключить.
- **Пережидание флуд-лимитов.** Короткие ограничения (короче
  `TELEGRAM_FLOOD_SLEEP_THRESHOLD`, по умолчанию 120 с) бот выжидает сам, не
  «долбя» сервер. Длинные — не приводят к спаму повторов: сообщение помечается в
  журнале с понятной причиной, аккаунт получает передышку.
- **Живучесть связи.** Обрывы соединения авто-переподключаются; сбой одного
  аккаунта больше не роняет остальные посреди занятия.
- **Понятные ошибки.** Если аккаунт попал под ограничение (`PeerFlood`), это видно
  в *Журнале работы* — дайте такому аккаунту паузу **минимум на сутки**.

**Как ещё снизить риск (организационно):**

- **Распределяйте аккаунты по разным «главным аккаунтам» (приложениям).** Заведите
  несколько приложений на my.telegram.org и в карточке каждого Telegram-аккаунта
  выберите своё — так активность не сходится к одному `api_id` (меньше похоже на
  «ферму»). Приложение выбирайте **до** подключения аккаунта: сменить его у уже
  подключённого — значит переавторизоваться.
- Не плодите лишние аккаунты: держите небольшой пул «живых», прогретых аккаунтов
  с историей и переиспользуйте их между группами.
- Не подключайте помногу новых аккаунтов с одного IP. Если аккаунтов много —
  задайте SOCKS5-прокси в `.env` (`TELEGRAM_PROXY_HOST/PORT/USER/PASS`; нужен
  пакет `PySocks`). По умолчанию прокси выключен.
- Оставляйте человеческие паузы между ответами (поля «Задержка» и «Пауза перед
  повтором» в сценариях) и не отправляйте всем один и тот же текст — используйте
  случайные числа `{от-до}`, они уже поддерживаются.

Все параметры защиты настраиваются в `.env` (раздел «Защита аккаунтов»), но
значения по умолчанию уже безопасны.

## Структура проекта

```
UsersBot/
├─ Инструкция-по-панели.pdf # пошаговая инструкция для не-программиста
├─ docs/build_manual.py     # генератор этой PDF-инструкции (pip install fpdf2)
├─ .env                     # единый файл настроек (секреты)
├─ docker-compose.yml       # боевой запуск: db + web + nginx + bot
├─ Dockerfile               # образ приложения (панель и бот)
├─ docker/nginx/            # конфигурация Nginx
├─ manage.py
├─ requirements.txt
├─ config/                  # настройки Django
└─ simulator/               # приложение системы
   ├─ models.py             # группы, аккаунты, приложения (api_id), сценарии, журнал, диалоги
   ├─ admin.py              # веб-панель (Jazzmin, карточка группы, раздел «Сообщения»)
   ├─ telegram_client.py    # авторизация по номеру/коду (Telethon)
   ├─ qr_auth.py            # авторизация по QR-коду
   ├─ bot_control.py        # вкл/выкл бота кнопкой из панели (флаг + heartbeat)
   ├─ worker.py             # фоновый процесс: сценарии, захват сообщений, отправка ответов из панели
   ├─ matching.py           # условия сценариев + подстановка {number}
   └─ management/commands/
      ├─ run_bot.py          # фоновый процесс (контейнер bot)
      ├─ ensure_superuser.py # автосоздание админа в Docker
      ├─ authorize_account.py# подключение аккаунта из терминала
      └─ seed_demo.py        # демо-данные
```
